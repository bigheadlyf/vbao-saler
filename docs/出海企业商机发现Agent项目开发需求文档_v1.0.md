# 出海企业商机发现Agent项目开发需求文档

文档编号：VBLA PRD 001  
版本：1.0  
日期：2026年10月23日  
状态：开发评审版，尚未签署项目验收基线  
适用对象：业务负责人、产品、开发、测试及运营人员

本项目建设面向跨境支付聚合产品的企业商机发现能力。系统定时发现目标地区的出海企业，结合公开证据判断潜在收款、付款、换汇及多渠道多币种整合场景，补充商务联系方式，生成Excel清单和简短日报，由销售人工核实及跟进。

本文件定义一期范围、功能规则、数据结构、交付规范及验收用例，可用于开发拆解和工作量评估。已确认的业务约束、建议默认值、外部依赖和待确认事项分别记录。进入开发评审不代表平台权限已经获得，也不代表采集和定时任务已经部署。

## 1 项目目标与需求基线

### 1 业务目标

为销售持续提供有主体依据、有出海证据、有公开商务联系入口的潜在客户，并说明为什么值得跟进、哪些问题仍需核实。系统同时记录实际覆盖范围、数据缺口和运行成本，支持后续扩展API及MCP接入。

### 2 已确认业务约束

| 编号 | 约束 | 业务口径 |
| --- | --- | --- |
| BR01 | 产品定位 | 聚合跨境支付，支持多渠道、多币种；具体国家、币种、渠道和准入条件以产品配置为准 |
| BR02 | 初期区域 | 珠海及周边城市，后续可配置；周边城市名单未最终确定 |
| BR03 | 客户类型 | 不限企业类型，不按行业或公司规模预先一刀切排除 |
| BR04 | 销售承接 | 每周能够跟进100个以上潜在商机 |
| BR05 | 一期交付 | 定时Excel清单和简短日报，人工跟进 |
| BR06 | 后续扩展 | 支持未来通过API或MCP读取数据及回传反馈 |
| BR07 | 现有资源 | 无企业数据服务及平台接口账号 |
| BR08 | 月度费用 | 搜索、模型调用及数据服务合计不超过人民币500元；开发人工费用不计入该运行预算 |

服务器、存储和外部通知费用是否包含在500元内列为待确认项。在确认前，方案按本地运行规划，不新增固定托管费用，也不默认开通付费服务。

### 4 成效指标

分别统计规则筛选后的待审核线索、人工确认有效线索、成功联系企业、确认需求企业及转商机企业。每周100个以上是规模规划及试运行验证目标，不视为固定保底产量，不允许用重复记录或弱证据候选凑数。

## 2 建设范围与阶段

### 1 一期必须交付

配置管理、种子和排除名单、多来源适配、企业发现与归一、出海识别、产品适配及需求分级、商务联系渠道补全、定时与补跑、增量更新、预算控制、结构化存储、Excel与日报生成、跟进反馈导入、运行审计和备份恢复。

一期交互以配置文件和命令入口为主，不要求开发网页后台。Excel由系统筛选后生成，销售在清单中审核并回传反馈；无需先有独立审核工作台才能使用。

### 2 有条件接入

抖音、小红书、微信公众号和视频号均纳入来源架构，但平台级持续采集取决于可用权限、访问规则、预算及实际接入测试。未获平台接入条件时，保留允许访问的公开页面和人工链接导入入口，明确标注覆盖不足。

### 3 后续建设

API及MCP服务、更多城市和来源、团队工作台、CRM同步、OCR及音视频转写。自动外呼、邮件、短信、私信、加好友和群发不在一期范围；跨境支付账户开立、交易执行、换汇操作和资金处理也不属于本项目。

| 阶段 | 主要成果 | 完成条件 |
| --- | --- | --- |
| M0 接入验证 | 来源可用性记录、产品配置骨架、样本及费用基线 | 至少两个独立来源可用，角色和保存用途明确，形成实际成本记录 |
| M1 一期开发 | 可运行程序、结构化存储、调度、Excel及日报、反馈导入 | 一期功能用例通过，故障及预算控制可验证 |
| M2 业务试运行 | 连续试运行记录、人工抽检、产量及质量报告 | 建议观察1至2周，完成质量与供给能力评估 |
| M3 扩展 | API及MCP，按条件增加平台来源 | 按单独版本范围评审和验收 |

阶段不绑定未经评估的工期。权限申请时间、外部服务采购及开发工作量在M0后估算。

## 3 角色与使用流程

| 角色 | 一期操作 | 主要责任 |
| --- | --- | --- |
| 业务负责人 | 提供产品范围，确认目标区域，审核试运行结论 | 定义适用客户及销售有效性 |
| 配置及运营人员 | 配置任务，导入种子，管理来源，补跑，处理异常 | 保证覆盖说明、成本和任务状态真实 |
| 销售人员 | 阅读清单，核对原文，联系企业，填写跟进反馈 | 确认实际需求、失效信息及拒绝联系 |
| 开发及维护人员 | 维护适配器、模型规则、数据迁移、备份与恢复 | 保证任务可恢复、结果可追溯 |

标准流程：读取配置及预算 → 规划检索 → 来源发现 → 提取正文 → 识别主体与排重 → 收集业务证据 → 判断出海与产品适配 → 识别需求 → 补充联系方式 → 规则校验与分级 → 生成Excel及日报 → 销售审核跟进 → 导入反馈 → 更新排除及复查计划。

每次分析使用冻结的配置、规则和模型版本。配置修改影响下一批次；指定补跑是否使用新版本必须明确记录。

## 4 功能需求

以下FR01至FR20均为一期必须实现的要求。文中标明“后续”的接口部署和平台扩展不纳入一期交付。

### FR01 任务与产品配置

支持设置目标城市及优先级、注册地或办公地或生产地口径、行业标签、企业类型、关键词及排除词、来源启停、运行频率、证据时间窗口、输出目录、预算和调用上限。企业类型默认为不限。

产品能力以国家或地区、币种、渠道、收付方向、主体类型、行业及准入条件建立矩阵，每个条件为支持、不支持或待确认。未知项不能自动解释为支持。配置保存前校验枚举、时区、路径、预算及必需凭据，错误时返回字段级提示。

### FR02 种子与排除名单

支持导入现有客户、企业种子、官网、账号及人工提交链接。每个排除项记录主体标识、原因、创建时间及适用范围，区分已合作、拒绝联系、已确认不适配及人工排除。

企业、联系方式和账号的拒绝范围分开记录，企业总机拒绝并不自动解释成所有同名个人拒绝，个人拒绝也不自动扩展至无关主体。明确拒绝信息优先于重新发现结果，不因再次采集而自动恢复跟进。

### FR03 来源适配与健康状态

每个来源配置访问方式、允许范围、配额、超时、重试、保存及导出限制。状态为待验证、待配置、可用、受限、故障或停用。展示最后成功时间、实际覆盖、失败原因及是否需要人工处理。

来源返回零结果、未运行、失败及配额不足分别记录。达到授权或访问限制时停止该来源，其他来源继续；来源内容及接口返回均不被视作系统操作指令。

### FR04 企业发现与检索规划

组合地域、行业、业务、痛点及联系方式关键词检索；支持简繁体、名称别名和必要的英文关键词。优先识别多渠道、多币种、多市场及境外收入与支出并存场景，保留不同行业的发现能力。

搜索摘要仅作为发现入口。对拟输出的关键业务结论继续核对原始页面；仅有摘要且无法取得原始依据时保留为待研究候选。搜索结果命中城市词不直接等于企业位于目标地区。

### FR05 企业主体归一与排重

企业、品牌、分支机构、平台账号及联系人分别建档。优先使用可靠主体标识归一；名称、域名、地址、官方互链及账号认证作为交叉证据。大陆统一社会信用代码和其他地区主体标识分别保存，不强制所有企业具备同一种标识。

同名、集团关系、同品牌不同运营主体及归属冲突进入人工核实队列，不静默合并。保留合并前ID映射、依据及历史；错误合并支持撤销。转载同一消息不算独立佐证。

### FR06 内容与证据归档

保留原始链接、规范化链接、来源、作者或发布主体、标题、原文必要短摘、内容发布时间、采集时间、核验时间及内容指纹。原文发布时间未知时为空，不用采集日期代替。

按来源允许范围保存必要证据，不默认长期保存全文或媒体。主张必须引用具体证据ID，证据能定位支持该主张的文字；页面失效、内容变化或关联冲突时更新核验状态并触发重新评估。

### FR07 出海业务识别

输出实际业务、筹备出海、仅有信号、未知或非目标。具体海外经营、出口订单、企业经营的海外店铺等可作为实际业务依据；岗位招聘、外文官网、境外展会或商标通常只作为辅助信号。

区分企业自身经营、代运营或顾问宣传、第三方转载、服务商广告及个人经验分享。不得仅因出现“跨境”“海外”关键词就认定出海业务成立。

### FR08 产品适配判断

输出适配、可能适配、不适配或未知，并列出已满足、未满足及待确认条件。已知不支持的国家、币种、渠道、主体或行业构成不适配依据；矩阵缺失导致的未知不得冒充已适配。

经营部、个体工商户及香港企业不因名称被默认纳入或排除。不得自行补充价格更低、到账更快、统一对账或自动路由等产品承诺。

### FR09 需求识别与理由生成

按收款、付款、换汇及支付整合场景分类，需求状态为明确表达、潜在场景、未知或已知当前无需求。每种需求分别保存证据及时间，避免一条公开收款需求被扩展成所有支付需求。

多平台经营、多币种结算、境外收支并存可形成潜在场景；明确询问服务商、账户、费用、流程或整合方案，在主体和语境匹配后可认定明确表达。推断项必须标明推断，未知交易金额、币种和频率不得估造。

### FR10 商务联系方式补全

支持企业电话、商务邮箱、联系表单、公开商务微信或企业微信入口、抖音、小红书、公众号及视频号入口。负责人商务电话和邮箱须有合法公开或相应授权依据、岗位及主体关联依据。

联系方式状态分别保存已提取、格式有效、归属核实、人工确认可用、失效、冲突或禁止使用。法定代表人不自动等同财务或采购负责人。格式正确不等于接通或送达，账号存在不等于可私信；不猜测邮箱、不还原隐藏号码、不自动拨打验证。

### FR11 线索准入与优先级

准入及分级执行第6章规则。产品适配、需求状态、证据强度和联系渠道分别展示，禁止只用一个不透明分数代表所有结论。优先级用于安排销售顺序，不表示成交概率。

输出建议核实的问题，例如真实交易币种、现有收付渠道、当前服务方式及是否需要整合；问题不得将推断写成已知事实。

### FR12 人工审核与纠错

机器筛选后的新线索默认待人工审核，可直接出现在销售Excel中。销售可标注通过、驳回或需补充，并更正主体、需求和联系方式。人工核实值与模型提取值分开保留，后续模型重跑不能无记录覆盖人工结果。

一期通过反馈文件和命令操作完成纠错、排除、合并及撤销合并，不依赖网页后台。冲突返回待处理清单。

### FR13 定时运行与任务控制

支持手动执行、定时执行、暂停、恢复、终止及指定阶段补跑。建议按周一至周五交付，默认不自动套用法定节假日及调休安排；时区、时间和日历可配置。

执行频率与交付时点分开设置，交付前预留处理时间。任务具有运行锁、心跳及阶段检查点；实例退出或机器休眠后识别中断，恢复后按策略补跑。终止前保存已完成数据，已提交的外部调用仍按真实结果计费。

### FR14 增量更新与重复交付控制

以稳定主体ID、内容指纹、证据ID和交付记录识别新增及变化。仅新增需求、关键联系入口、重要证据或业务状态变化进入重要变化清单，纯排版或重复转载不触发提醒。

同一批次重试沿用幂等键；已交付企业不再次计入首次新增。合并、拆分和跨平台重发现不能重置首次交付标识。来源失效不能直接解释成企业停止出海或无需求。

### FR15 费用预算与调用配额

月度搜索、模型和数据服务共用500元费用池，分别记录已结算费用、保守估算费用及在途预留。每次付费调用前原子校验剩余额度并预留最高预计费用，完成后核销，多任务并发不能重复使用同一额度。

达到350元、450元时记录预警，执行将导致超过500元的调用前必须停止。未知定价或无法界定费用上限的收费来源不启用。外币费用按可追溯的换算配置计入人民币；实际费用超出预留时记录异常并停止新增收费调用，不掩盖账单差异。

预算按配置时区自然月重置，保留月度台账。在途请求跨月时不因预算重置丢失预留，原调用额度按发起月份归属并持续跟踪。免费调用仍受来源配额及任务资源上限约束。

### FR16 Excel与日报生成

按第8章规范生成Excel及简短日报。即使没有新线索或来源部分失败，也生成真实运行摘要，不使用历史记录冒充本期新增。临时文件校验完成后原子发布，失败时保留可恢复状态。

区分文件生成成功和外部发送成功。一期默认本地目录交付，外部发送仅在明确配置且具备授权时启用。发布失败的批次不写入成功交付记录；已发布文件因进程中断未记账时，依据批次清单恢复，不重复计为新增。

### FR17 跟进反馈导入

支持读取系统生成的Excel反馈表，按企业ID、线索ID及版本导入审核结论、负责人、联系结果、需求核实、无效原因和下次跟进时间。只允许修改规定的反馈字段，不能通过反馈任意改写证据及费用台账。

采用反馈事件ID或批次及行指纹去重。未知ID、非法枚举及过期版本逐行返回错误，不静默覆盖更新的数据；有效行可独立导入。相同文件重复导入不产生重复事件。

### FR18 运行审计与诊断

保存每次任务的计划时间、开始结束、配置版本、来源覆盖、阶段数量、失败及跳过原因、费用、导出位置和下一次运行计划。敏感凭据及完整个人联系方式不写入普通日志。

支持查询最近任务、预算余额、来源健康及失败明细。人工重跑、排除、纠错、导出、删除和恢复操作均留下必要审计记录。离线无法实时发出告警时，恢复后在日报中明确标注。

### FR19 保存期限与备份恢复

企业档案、联系人、证据摘录、原始内容、报告及日志分别配置保存期限，来源保存限制优先。期限未配置时不启用持续采集，期限值列入上线配置确认，不擅自无限期保存。

支持必要的更正、删除及停止联系处理；删除覆盖数据库、后续导出、受控历史文件及备份恢复规则。对已分发到管理范围之外的文件记录处置状态，不能宣称远端副本已自动删除。仅在存在相应处理依据和必要性时保留最小拒绝匹配信息，避免再次导入。

每日任务结束后备份结构化数据、配置版本和交付清单；备份与主数据分开保存并按期限轮换。恢复后先核对预算及在途调用、拒绝名单和已交付记录，核对完成前不自动恢复收费采集。

### FR20 对后续接口扩展的支持

一期结构化存储独立于Excel，企业、线索、证据、联系人、任务及反馈具有稳定ID与版本。查询、详情、增量、反馈回写、任务及预算状态的业务边界独立于导出实现。

后续API与MCP复用同一业务服务，支持授权、分页、过滤、增量及幂等写入。对外接口部署、外网访问及MCP服务发现不作为一期完成条件。

## 5 来源与接入依赖

| 来源编号 | 来源类别 | 主要用途 | 一期状态与条件 |
| --- | --- | --- | --- |
| S01 | 搜索引擎或搜索服务 | 发现官网、文章及公开账号 | 服务及凭据待选型，需验证允许调用方式、费用和实际可用性 |
| S02 | 企业官网及官方页面 | 主体、业务和商务入口核实 | 优先接入，逐站确认允许访问及保存范围 |
| S03 | 政府、园区、商协会及展会 | 本地企业发现及业务线索 | 优先验证独立来源，历史名单仅作候选依据 |
| S04 | 招聘及行业平台 | 出海布局辅助信号 | 条件接入，识别招聘中介、转载及实际用人主体 |
| S05 | 抖音 | 企业账号及出海内容 | 官方搜索存在权限要求，权限及配额待验证 |
| S06 | 小红书 | 公开经营内容及账号 | 全站检索能力未确认为现成依赖，官方电商接口不等于全站内容检索 |
| S07 | 公众号及视频号 | 企业公开内容及联系入口 | 分开验证；不预设存在可直接使用的全网检索接口 |
| S08 | 商业企业数据服务 | 补充企业主体及联系渠道 | 非一期必需项，无现成账号，启用前明确合同用途及费用 |

同一个搜索服务返回多个域名，需分别记录实际内容来源；两个检索关键词不算两个独立来源。M0的“至少两个来源”以独立发布主体或数据服务确认，不要求两家付费搜索服务。

来源上线记录至少包含访问方式、授权及用途、字段、保存限制、频率及配额、价格上限、成功样本和失败行为。遇验证码、授权失效、访问控制或平台限制时停止该来源或转人工处理，不绕过控制。

## 6 判断规则与统计口径

### 1 核心状态

| 维度 | 状态值 | 使用规则 |
| --- | --- | --- |
| 出海 | ACTUAL PREPARING SIGNAL UNKNOWN NON_TARGET | ACTUAL需实际业务证据，招聘等辅助信号不单独满足 |
| 适配 | FIT POSSIBLE UNFIT UNKNOWN | FIT需关键产品条件核实；UNKNOWN不能自动通过A级 |
| 需求 | EXPLICIT POTENTIAL UNKNOWN NONE | 每类需求分别判断；无公开表达不等于NONE |
| 联系 | ATTRIBUTED UNVERIFIED MISSING BLOCKED | ATTRIBUTED表示归属有依据，不表示已接通 |
| 审核 | PENDING APPROVED REJECTED NEEDS_INFO | 新输出默认为PENDING，人工通过后才为APPROVED |
| 跟进 | UNCONTACTED CONTACTED NEED_CONFIRMED OPPORTUNITY WON LOST DEFERRED INVALID | 与审核状态分开维护，拒绝联系另有强制阻断标识 |

人工可以因新证据变更状态，但必须记录依据。未成交可以重新评估，拒绝联系不会由模型评估自动解除。

### 2 线索分级与交付准入

| 等级 | 必须满足的条件 | 一期去向 |
| --- | --- | --- |
| A | 主体和地域已核实，ACTUAL，FIT，近期EXPLICIT，至少一个ATTRIBUTED商务入口，无排除条件 | 新增或变化清单，标明人工审核状态 |
| B | 主体和地域已核实，ACTUAL，FIT或POSSIBLE，至少POTENTIAL，至少一个ATTRIBUTED商务入口，无排除条件 | 新增或变化清单，待核实条件必须可见 |
| C | 辅助信号、主体或地址待核实、需求未知、联系归属不明等，尚未达到A或B | 待研究池，不计入可跟进商机目标 |
| 排除 | 已合作、明确拒绝、已确认不适配或非目标主体 | 不进入新客销售清单，保留必要原因记录 |

产品矩阵缺少全部关键条件时为UNKNOWN，先补齐至少可形成POSSIBLE的产品条件，不能通过规则默认设为适配。某类企业没有公开负责人直联号码时，已核实企业商务邮箱、总机或联系表单可满足商务入口要求。

### 3 时间与证据

建议明确需求优先核查近30天内容，业务动态优先近90天，窗口均可配置。内容发布时间未知、过期或归属有争议的需求不能作为“近期明确需求”进入A级。

同一需求可有多个独立证据，转载按原消息归并。证据出现否定、过期、失效或来源冲突时重新判断；旧证据降低排序，不自动证明当前无需求。排序依次考虑等级、需求时效、聚合场景关联、关键条件完整性及最近核验时间；并列用稳定ID排序，保证可复现。

### 4 数量及质量

周定义为配置时区周一00:00至下一周一00:00。周新增按首次成功发布且满足A或B规则的去重企业计数，PENDING与APPROVED分开报告。重要变化、同企业多个联系人、跨平台重复、已合作客户及C级不计入新增。

实际业务有效率＝人工审核通过的新线索数÷已完成人工审核的新线索数；未审核不得记为无效或有效。联系成功率以实际尝试联系的企业为分母；需求确认率注明以已联系还是已审核企业为分母。不得报告无法知道分母的“全网召回率”。

## 7 数据结构与追溯

### 1 实体关系

企业可关联多个品牌及账号、联系人、证据和历次评估。一个评估支持多个需求类型，所有结论引用证据。线索记录销售与交付状态；任务批次关联实际来源、调用成本及报告。反馈作为事件追加，保留修订历史。

| 实体 | 主键及核心字段 | 关键约束 |
| --- | --- | --- |
| Company | company_id，法定名，别名，主体类型，注册及办公生产地址，地区状态，官网 | 名称不作唯一键；标识、合并及历史ID可追溯 |
| CompanyIdentity | identity_id，company_id，标识类型及值，地区，账号或品牌，证据ID | 标识按地区和类型规范化；账号归属冲突不得强制唯一关联 |
| Source | source_id，类型，允许用途，凭据引用，配额，价格及健康状态 | 凭据只保存引用，不进入导出 |
| SourceDocument | document_id，source_id，URL，指纹，发布时间，采集及核验时间 | URL与内容版本可多次出现，时间字段不可混用 |
| Evidence | evidence_id，company_id，document_id，主张类型，原文摘录，归属依据，状态 | 拟输出结论必须可定位证据；证据失效保留状态历史 |
| Contact | contact_id，company_id，类型，值，姓名及岗位，商务用途，验证状态 | 同一号码可关联多个主体，不能据此单独合并企业 |
| ContactEvidence | contact_id，evidence_id，关联说明，核验时间 | 联系方式与多个证据通过关联保存，不造笛卡尔重复 |
| Assessment | assessment_id，company_id，四维结论，等级，理由，版本，证据列表 | 模型、提示、规则和产品矩阵版本全部可定位 |
| Lead | lead_id，company_id，当前评估，审核及跟进状态，负责人，版本 | 主体归一后保留稳定线索映射，禁止重复首次交付 |
| RunBatch | run_id，计划及实际时间，阶段，状态，配置版本，计数，错误 | 重试批次及幂等键可关联，阶段完成可恢复 |
| Delivery | delivery_id，run_id，企业及线索清单，路径，校验值，发布时间，状态 | 同一企业首次成功交付只计一次；生成与发送状态分离 |
| Feedback | feedback_id，lead_id，导入批次，原版本，更新字段，操作者及时间 | 事件追加；重复导入幂等，过期版本返回冲突 |
| CostLedger | call_id，run_id，来源，费用月份，预留，估算及实际金额，状态 | 月度预算校验与预留具备原子性；未知账单保留未结算状态 |
| Suppression | suppression_id，对象及匹配范围，原因，依据，时间及状态 | 拒绝与删除规则独立于模型结果，恢复备份后继续生效 |

### 2 通用字段与约束

所有可变实体包含created_at、updated_at和record_version。时间内部使用带时区时间戳，导出显示业务时区及UTC偏移；金额使用十进制定点值并保存币种及换算依据。未知值使用空值及未知原因，不使用猜测值或用0代替未知金额。

电话、邮箱、账号和URL保留原始值及规范化值；规范化只用于匹配，不能丢弃国家区号或改写主体事实。自动合并必须记录依据与可恢复映射；采集重试、模型重跑及反馈导入不得破坏ID稳定性。

## 8 Excel与日报交付规范

### 1 文件及工作表

文件名称包含业务日期、批次及结构版本，例如leads_20261023_run001_v1.xlsx和daily_20261023_run001.md。命名仅为格式示例，不代表已产生该日真实线索。

| 工作表 | 行粒度 | 必需内容 |
| --- | --- | --- |
| 本期新增 | 每个首次交付企业一行 | 企业ID、线索ID、批次、名称、地址口径、行业、出海状态、需求、适配及待确认项、等级、审核状态、商务入口、证据引用、时间、建议核实问题 |
| 重要变化 | 每个企业的本期重要变化一行 | 企业及线索ID、变化类型、变化前后、触发证据、更新时间、跟进状态 |
| 联系方式与证据 | 每条CONTACT或EVIDENCE记录一行 | record_type、企业及线索ID、contact_id或evidence_id、关联ID、内容、来源、发布时间、核验及验证状态 |
| 运行摘要 | 每个指标或来源状态一行 | 实际覆盖、成功失败及未运行来源、A及B及C数量、费用、缺口、计划与实际时间、补跑情况、版本 |
| 跟进反馈 | 每条线索一行 | 企业及线索ID、record_version、审核、销售负责人、联系结果、需求核实、无效原因、下次跟进、备注 |

主表显示便于联系的已核实商务入口；多个联系方式通过关联表完整保留。联系方式与证据按record_type区分，不能因多个联系人和多个证据相乘而增加商机数量。

### 2 可用性与一致性

主表冻结表头、启用筛选并设置合理列宽和自动换行；来源链接可点击，电话和平台ID按文本保存。外部文本以文本单元格写入，防止以等号等字符开头的内容被执行为公式；不包含宏、自动执行对象或未经允许的外部数据连接。

所有必需列在空清单中仍保留。表内企业ID及证据引用无悬空关联；摘要数量与实际企业去重结果一致。发布前检查文件可正常读取、结构版本、关联及内容完整性，失败时不覆盖最近一次可用报告。

### 3 日报内容

日报包含计划及实际运行时间、本期新增A及B数量、重要变化、待研究C级数量、需优先核实项、实际来源覆盖、失败及限制、费用与剩余预算、周新增进度及Excel位置。避免在日报正文重复分发完整个人联系方式。

无新增时说明是真实零结果、未运行、来源失败还是预算停止。周汇总按第6章定义统计，不将补跑批次简单相加。报告生成成功不能写成销售已收到或已确认需求。

## 9 调度与异常处理

| 场景 | 必须行为 | 报告结果 |
| --- | --- | --- |
| 单来源失败 | 有限重试后隔离该来源，继续其他来源 | PARTIAL及受影响范围 |
| 来源限流或授权失效 | 遵循返回限制，停止该来源或等待下次运行 | 需配置或恢复时间，零结果与失败分开 |
| 机器离线或休眠 | 恢复后识别漏跑，按配置补跑 | 实际补跑时间及迟交说明 |
| 任务重叠 | 使用锁阻止重复执行；失效锁须依据心跳及进程状态释放 | 已在执行或恢复状态 |
| 模型超时或输出无效 | 有限重试，结构校验失败进入待处理 | 不生成无依据业务结论 |
| 页面失效或变化 | 标记证据核验状态并重新评估依赖结论 | 重要变化或待研究 |
| 预算不足 | 调用前停止新增收费请求，保留进度并生成摘要 | BUDGET_STOPPED及缺口 |
| 导出中断 | 校验批次清单及临时文件后恢复发布 | 不重复交付或重置首次新增 |
| 反馈冲突 | 有效行独立导入，冲突行返回原因 | 成功、重复、冲突及失败行数 |

任务状态为QUEUED、RUNNING、SUCCEEDED、PARTIAL、FAILED、CANCELLED或BUDGET_STOPPED。任务状态、来源状态、文件生成状态和发送状态分开保存。仅部分阶段完成时不能报整体成功。

## 10 非功能要求

| 编号 | 要求 | 验证方式 |
| --- | --- | --- |
| NFR01 | 结果可追溯 | 任一输出结论能定位主体、证据和所用配置及规则版本 |
| NFR02 | 故障可恢复 | 在采集、模型调用、导出及记账阶段中断后，能由检查点恢复且不重复计费预留或新增 |
| NFR03 | 数据和模型边界 | 外部页面中的指令不改变任务和权限；模型只返回受校验结构，不能直接决定任意工具操作 |
| NFR04 | 费用受控 | 并发预算预留、阈值预警及停止调用用例通过，账单差异可审计 |
| NFR05 | 最小信息处理 | 凭据脱离正文及导出，个人联系方式不进入无关模型输入及普通日志，导出目录受控 |
| NFR06 | 变更可维护 | 地域和规则配置无需改代码；来源适配器故障不影响其他来源 |
| NFR07 | 运行可观察 | 能查询批次、阶段、来源状态、计数、预算及失败原因，空结果有解释 |
| NFR08 | 交付兼容性 | Excel在目标用户实际使用的软件中打开并完成筛选、链接和反馈回传验收，具体软件版本上线前记录 |
| NFR09 | 备份可用 | 恢复测试核对企业、证据、拒绝名单、预算与交付记录，一致后才恢复任务 |

性能及容量应在M0确定的机器和调用配额下实测。建议至少以2000条企业档案验证增量、导出及反馈处理；耗时基线与可接受窗口在技术评审中记录，不以未测试数值承诺响应时间。系统持续可用性依赖运行设备在线和外部服务可用。

| TC20 | FR20 | 追查Excel某行及导入反馈 | 可由稳定ID取得相同企业、证据和版本，无需解析历史Excel作为主库 |

### 3 试运行与质量抽检

建议试运行1至2周，积累约100家候选，按来源和等级分层抽检至少50家，不足则全量并报告样本不足。候选总量与A及B商机数量分别报告，不将100家候选等同于100条可跟进商机。

A级准确性定义为抽检A级中实际满足全部A级条件的比例，建议目标不低于80%，为待评审质量目标；没有A级样本时标为无法评估，不能记为100%。同时报告主体归属错误、联系方式归属错误、证据缺失及人工确认需求情况。

系统规则验收要求：输出主张和商务联系渠道均有具体证据引用；必需字段及关联有效；重复运行不产生重复新增；渠道失效真实可见；预算停止及反馈冲突按预期处理。

若在500元预算及已确认地域内达不到每周100个以上合格新线索，应提交实际供给、单条成本、限制及可选调整方案，不能自动扩展城市、增加预算或降低准入门槛。
