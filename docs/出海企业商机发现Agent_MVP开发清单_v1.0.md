# 出海企业商机发现Agent MVP开发清单

版本：1.0  
日期：2026年10月23日  
依据：出海企业商机发现Agent项目开发需求文档1.0  
定位：完整一期之前的最小交付子阶段，用于验证真实采集、商机质量与成本。本清单界定MVP范围，不将完整一期FR01至FR20全部设为MVP必选。

## 1 最小交付目标

通过一到两个数据源的真实爬虫，自动执行“发现企业 → 数据存储和排重 → 商机分析 → 补充公开商务联系入口 → 输出Excel和日报”，支持定时运行，保留来源证据，运行费用不超过每月500元。

MVP以珠海为初始样本范围，城市名单可配置；周边城市具体启用名单沿用正式需求中的待确认项。不限定企业类型，重点判断跨境收款、付款、换汇及多渠道多币种整合场景。每周100个以上是后续供给规模验证目标，不能以重复企业或低质量线索填充产量。

## 2 首发数据源

采用“一种公开发现来源＋一种企业官网补充来源”的两类采集器，先把具体站点适配范围限制在小范围，不建设通用全网爬虫。

| 采集器 | 最小范围 | 采集目标 | 接入条件 |
| --- | --- | --- | --- |
| A 企业发现爬虫 必须 | 从一个已验证站点的指定栏目、名单页或分页列表出发，进入详情页；优先珠海企业名录或公开出口企业公示 | 企业名称、公开主体标识、地区及依据、业务描述、原始页面、发布时间；公开商务联系方式或官网链接如有则提取 | 可允许访问的HTML正文，取得真实样本；配置入口URL和页面上限，无需平台账号 |
| B 企业官网爬虫 条件必需 | 从已核实或人工补充的官网映射出发，仅抓首页、关于我们、业务介绍、联系我们等少量页面 | 出海业务、多渠道多币种信号、企业商务电话和邮箱、公开账号及表单入口 | 先核实网站与企业归属，按域名白名单和深度限制访问；无可用官网时记录缺失，不猜测域名 |

原则上优先交付A＋B。若单一来源的公开详情已能提供业务证据和至少一种归属明确的商务入口，可仅用A完成MVP；若A只有企业名称，B必须启用，不能用一份名单代替商机闭环。

首发候选站点可在珠海企业服务平台的企业名录和广东税务官网珠海出口企业公示中选择一个。选定前需验证列表、正文、分页、允许访问范围及字段；网页被搜索引擎收录不代表程序已成功接入。本轮资料核对中，税务候选页直接读取超时，企业服务平台首页未返回可解析正文，因此两者均为待验证候选，不标为已打通。

候选参考：

- [珠海企业服务平台](https://www.zhsme.org.cn/)
- [珠海高新区2025年度出口企业公示名单](https://guangdong.chinatax.gov.cn/zhgkml/zhgxgkml_qttzgg/2026-06/03/content_2468a3e1983e4c399ed7dc477f9c1288.shtml)

以上候选中，企业名录不直接证明出海，历史出口公示也不能证明当前支付需求。出口分类等级不用于推断企业需求或信用。首发站点以接入验证结果为准。

官网域名优先来自来源详情的链接或经核实的少量人工映射；无官网发现能力时不声称能自动发现全部官网。搜索引擎作为后续发现增强，本MVP不另建搜索平台爬虫或强制采购搜索接口。这里的两个数据源指两类限定范围的采集入口，不承诺只处理两个企业域名。

## 3 必须开发的功能清单

| 编号 | 功能 | 最小实现 | 完成标志 | 正式需求映射 |
| --- | --- | --- | --- | --- |
| MVP01 | 基础配置 | 一个配置文件设置城市、来源入口、官网白名单、关键词、产品简介及已知禁入条件、排除企业、页数、调度、模型和费用上限、输出位置及保存期限 | 无需改代码即可更换入口、城市和关键词；缺必需配置时有明确提示 | FR01 FR02 |
| MVP02 | 一到两个来源的真实爬虫 | A及按第2章条件启用B；抓取列表和正文，提取企业、业务、商务入口和来源时间；含限速、超时、有限重试 | 真实页面抓取并落库；零结果和失败分开；限制页面不绕过访问控制 | FR03 FR04 FR06 |
| MVP03 | 数据存储和基础排重 | 使用SQLite保存企业、来源页面、联系方式、分析结果和任务；按可靠主体标识归一，名称规范化及官网辅助检查，冲突保留待核实 | 重跑不重复建企业；分析能反查原始链接和证据摘录；同名主体不强行合并 | FR05 FR06 FR14 |
| MVP04 | 商机分析 | 一个模型、一版提示词、结构化输出；判断出海状态、收付款或换汇场景、多渠道多币种关联、需求状态、产品适配待确认项、优先级及理由 | 每条判断绑定已获取证据；未知返回未知；非法输出校验失败不当作合格分析 | FR07 FR08 FR09 FR11 |
| MVP05 | 公开商务联系方式 | 只从已采集页面提取公开企业电话、商务邮箱、联系表单或企业公开账号；保存归属及来源 | 至少一种归属明确入口才能进入可跟进清单；负责人直联缺失可留空；不猜测号码邮箱 | FR10 |
| MVP06 | 商机输出 | 每次生成一个Excel和一个简短Markdown日报；无结果时仍生成真实摘要；按优先级排序，首次新增与存量变化分开 | 文件可打开，证据可点击；数量按企业去重；失败不冒充没有商机 | FR16 |
| MVP07 | 手动和定时运行 | 单机执行入口＋操作系统定时任务；一次只允许一个实例；可手动完整重跑，无需复杂断点编排 | 指定时间触发完整流程；重跑不重复创建数据或重复记首次新增；机器离线后下次运行报告漏跑 | FR13 FR14 |
| MVP08 | 最小费用和故障控制 | 本地任务日志、月费用台账、调用前预估上限和检查、页数及调用数上限；单机运行，禁止多实例突破预算 | 500元预算不足时停止新增收费调用；未知定价来源不启用；已完成结果仍可输出，停止原因可见 | FR15 FR18 |

不依赖独立后台、分布式任务队列、多个模型、复杂客户画像或接口服务才能完成上述功能。为保证最小成本，先做格式提取、排重及已采集内容复用，再调用模型；未变化的内容不重复分析。

已有三个客户纳入本地已合作排除配置，按可确认主体匹配，不按模糊名称大范围排除。明确拒绝联系的企业或渠道同样支持本地排除，重跑不能自动解除。

## 4 最小数据与分析结果

SQLite至少保存以下五组记录，可采用关系表及必要的JSON字段，不要求完整一期的14类实体全部独立建表。

| 数据组 | 最少保存字段 |
| --- | --- |
| 企业 | enterprise_id、名称、公开主体标识如有、城市及依据、官网如有、是否已合作或排除、首次及最近发现时间 |
| 来源页面 | page_id、enterprise_id或待关联状态、来源、URL、标题、发布时间可为空、采集时间、必要证据摘录、内容指纹、采集状态 |
| 商务联系方式 | contact_id、enterprise_id、类型、公开值、来源page_id、归属依据、验证状态、最近核验时间 |
| 分析结果 | analysis_id、enterprise_id、所用page_id列表、出海状态、需求类型及状态、聚合场景、适配及未知项、等级、理由、建议核实问题、分析时间和模型提示规则版本 |
| 运行及交付 | run_id、计划和实际时间、来源结果、各阶段数量、费用月份及调用记录、导出状态和文件、首次交付企业记录、错误原因 |

已采集的完整正文如需短期缓存，按来源条件及配置期限处理，不默认长期保存全文。时间分别保存发布时间和采集时间，不混用。模型输入仅包含判断所需证据，网页中的操作指令不能改变采集和工具权限。

商机分级沿用正式文档的A、B、C口径，MVP实现简化的规则判断：

- A：企业及地域可靠，有实际出海证据，产品关键条件已适配，近期明确表达相关需求，至少一个归属明确的商务入口。
- B：企业及地域可靠，有实际出海及潜在场景证据，无已知不适配条件，产品至少可能适配，至少一个归属明确商务入口；缺失条件清楚列出。
- C：主体、地址、出海证据、需求或联系归属仍不足，进入待研究清单，不计入可跟进商机。

没有产品关键规则时不能自动标已适配；全部关键适配条件未知时也不能凭产品简介直接生成B级。可先研究企业并输出C级及缺口，待补规则后重分析。未公开需求不等于没有需求，历史出口名单不等于近期有采购意愿。

## 5 最小输出格式

Excel保留三张表即可，MVP不要求完整一期五表结构。

| 工作表 | 内容 |
| --- | --- |
| 可跟进商机 | 本期新增或重要变化的A及B级，企业名称、城市、出海依据、需求类型及状态、适配与未知项、等级、联系方式和来源、证据日期、建议核实问题、人工结论及备注空栏 |
| 待研究 | C级及缺少信息，保留企业ID、来源和原因，不冒充可跟进量 |
| 运行摘要 | 本次抓取、成功失败和未运行来源、去重企业数、首次新增与变化数、A及B及C数量、费用与余额、文件生成及实际运行时间 |

所有企业行均保留enterprise_id、run_id及最新analysis_id。多来源证据及多联系入口可作为同一企业行的换行文本或单元格链接展示，数据库保留关联，不因字段展开而重复计算企业。多个来源链接需分别可定位，不能只提供平台首页。

Excel冻结表头、可筛选，电话及账号写为文本，外部内容不作为公式执行。不要求自动接通电话、验证邮箱送达、抓取所有负责人联系方式。

日报只需一页以内的文本摘要：新增可跟进企业数、重要变化、待研究数、优先关注项、来源失败或覆盖缺口、当月费用和Excel路径。报告默认保存本地目录，外部自动发送延后。销售人工审核清单，填写备注；自动反馈导入延后。

## 6 MVP不做与延后项

| 延后功能 | MVP替代办法 |
| --- | --- |
| 抖音、小红书、公众号及视频号的专用平台爬虫 | 有公开账号入口时作为联系方式提取，暂不做平台内容持续搜索 |
| 搜索引擎专用采集及付费企业数据库 | 固定发现来源＋公开详情＋已核实官网映射 |
| 通用全网适配、PDF和图片OCR、视频语音转写 | 首批限定可解析HTML；其他内容记录待人工处理 |
| 完整产品能力矩阵和复杂评分模型 | 产品已知规则、禁入条件及未知项，A及B及C规则分级 |
| 自动合并集团品牌及撤销复杂合并 | 可靠标识归一；冲突不合并并留待人工处理 |
| 后台、销售权限体系及自动认领 | 配置文件、单机受控目录、人工使用Excel |
| 跟进反馈自动导入和闭环学习 | Excel人工备注；已合作和拒绝名单通过配置维护 |
| API、MCP和CRM | 稳定ID及结构化存储，保留扩展空间 |
| 分布式调度、复杂断点续跑和可视化监控 | 单实例定时任务、幂等完整重跑、日志与费用台账 |
| 自动外呼、群发、私信和自动加好友 | 人工选择适当商务渠道跟进 |

数据保存期限、来源及联系归属、停止联系、凭据保护、预算限制和证据追溯仍属于MVP基础边界，不随复杂功能一起删除。数据备份可先采用任务结束后的SQLite一致性副本及配置副本，不要求完整一期的自动恢复编排。

## 7 开发顺序与最小验收

推荐开发顺序：来源接入验证 → MVP01及MVP02 → MVP03及MVP05 → MVP04 → MVP06 → MVP07及MVP08 → 端到端样本验收。基础限速、费用检查和日志从实际调用开始就生效，不等到最后再控制。

| 用例 | 验收要求 |
| --- | --- |
| MVT01 真实采集 | 至少一个真实公开来源能从列表进入正文并落库；按第2章需要补充时，官网爬虫同步验证，模拟数据不算来源打通 |
| MVT02 最小闭环 | 一批真实企业完成采集、存储、分析和输出；建议20家作为目标样本，供给不足则说明实际范围，不用虚构企业补足 |
| MVT03 来源与存储 | 任一分析结论和商务入口可反查企业、原页面及摘录；缺失时间和字段留空并有原因 |
| MVT04 重复运行 | 同一来源重复执行，企业不重复创建，未变化内容不重复分析，已交付企业不再次计入首次新增 |
| MVT05 判断质量 | 辅助信号不冒充实际出海；未知产品条件和旧需求不冒充A级；缺入口企业进入待研究而非合格商机 |
| MVT06 可跟进结果 | 至少有真实、证据成立的A或B记录进入可跟进表才能证明业务闭环；如果全为C，只能认定技术链路跑通，来源或产品配置仍需调整 |
| MVT07 输出可用 | Excel可打开和筛选、链接可定位、电话文本正确，日报和数据库去重计数一致；新增与变化分开 |
| MVT08 定时与失败 | 验证一次定时触发、单实例限制，以及来源失败或零结果时的真实摘要输出 |
| MVT09 费用停止 | 在模拟或测试额度下验证调用前阻止超限；真实账单及估算可追溯，当月500元上限不能被重跑绕过 |
| MVT10 基础排除 | 已合作和拒绝联系记录再次出现时，不进入新客可跟进表，不因模型重分析恢复 |

MVP验收以技术闭环、至少一条真实可跟进输出、必要保护及实际成本记录为准。20家样本和每周100个以上规模分别属于建议样本目标和供给验证目标，不是可以用弱证据完成的固定产量。

最终交付：可运行采集分析脚本、配置示例、SQLite数据库、Excel及日报样例、定时任务说明和上述验收记录。实际目标站点、模型价格及运行环境完成验证后再估算开发工期。
