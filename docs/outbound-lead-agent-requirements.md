# 出海企业跨境收付款线索 Agent 功能需求草案

版本：v0.2；日期：2026-10-23；状态：已补充业务反馈，剩余假设待确认。本文为需求定义，尚未部署采集、调度或交付任务。

## 1. 目标与已知条件

定时从公开、允许访问或经授权的数据来源中发现目标区域企业，识别其出海业务及跨境收款、付款、换汇的服务机会，补充公开商务联系渠道，形成可追溯、可审核、可跟进的销售线索。

用户已确认：“首付款需求”实际指跨境收款、付款、换汇等服务。初期定位珠海及周边城市，区域后续可配置。希望覆盖搜索引擎、公开互联网平台、抖音、小红书、微信等来源。

本轮已确认：

| 项目 | 已确认内容 |
| --- | --- |
| 产品定位 | 聚合跨境支付能力，支持多渠道、多币种；用户描述覆盖大部分国家地区及货币，准确支持范围待产品清单确认 |
| 客户范围 | 不限定企业类型，不预设只做制造业、外贸公司或电商卖家 |
| 现有客户种子 | 香港帝晶燈飾有限公司、东莞市东城品德电子经营部、纳优服飾有限公司；名称由用户提供，未进行公开主体核验 |
| 第一版使用方式 | 定时Excel线索清单＋简短日报，人工跟进 |
| 后续接入 | 预留API及MCP接入能力 |
| 跟进能力 | 每周可跟进100个以上潜在商机；作为交付规模规划依据，不等于已验证的获客产量 |
| 现有数据资源 | 无企业数据服务或平台接口账号，不将任何付费库或平台搜索权限视为现成能力 |
| 月预算 | 搜索、模型调用和数据服务每月合计不超过人民币500元；服务器及存储等是否包含在内尚待确认，第一版建议本地运行以避免新增固定托管费用 |

尚待确认：产品名称与服务提供方、精确支持范围与准入限制、首批城市及地址口径、文件交付位置、运行时间和运行环境。本稿中的地域扩展、调度频率、分级规则及验收数值均为建议，不构成已确认需求或产量承诺。

业务成功标准：让销售更快找到适合产品、有事实依据、能尝试联系的企业；发现数量不能单独代表效果。

## 2. 使用者与工作闭环

- 业务管理员：配置地区、行业、产品适用范围、关键词、来源、预算、运行计划与权限。
- 销售：审核证据、认领线索、核实需求、记录跟进及无效原因。
- 运营人员：处理来源不可用、账号授权过期、重复主体、归属冲突等问题。

工作流：配置任务 → 多渠道发现 → 企业主体归一 → 出海证据识别 → 产品适配与需求分级 → 联系方式补全 → 人工审核 → 清单或工作台交付 → 跟进反馈 → 更新线索与规则。

系统自动生成的是待核实线索。明确需求与成交意愿的确认，需要企业公开表达或人工接洽的依据。

| 配置项 | 需求 |

| 地区口径 | 分开记录注册地、办公地、生产地；支持选择命中哪类地址，默认建议注册地或办公地 |

| 产品画像 | 支持的企业类型、交易场景、国家地区、币种、平台、起量条件和不适用范围 |
| 检索策略 | 地域词、行业词、业务信号词、需求词、负面词组合；支持别名、品牌及中英文检索 |
| 来源 | 启停、优先级、访问方式、权限范围、调用配额与保存限制 |
| 时间 | 发现窗口、复查周期、证据有效窗口、运行时段与时区 |
| 资源 | 单次/每日查询量、页面量、模型调用量、费用上限与联系人补全深度 |

不限定行业不等于不需要优先级：建议同时覆盖不同行业，优先检索存在多个收付渠道、多个币种或多个市场的实际经营场景。已成交客户只作样本种子、相似企业发现和排除依据，不限制后续发现范围。

默认将用户提供的三个现有客户标为“已合作，排除新客清单”。香港和东莞的客户样本不代表首批采集范围自动扩展至香港或东莞；注册地、法定名称、企业类型及关联企业关系仍需核验，不按名称直接补全。经营部等主体能否准入保留未知，不在未获得产品规则时直接排除或标成已适配。

关键词示例：“珠海 + 外贸出口”“中山 + 海外订单”“江门 + 亚马逊运营招聘”“企业名 + 收款/结汇/联系方式”。仅为检索起点，不能直接作为需求成立的依据。

| 微信 | 公众号文章、企业官方公众号、视频号公开内容 | 按公众号、视频号分别验证；先支持可合法访问的公开页面、人工提交链接、授权来源；不把公众号管理接口当作全网搜索接口 |
| 商业企业数据服务 | 补充主体与企业公开联系方式 | 作为可选授权来源；确认合同用途、保存及导出限制，不默认有账号或预算 |

冷启动要求：先建立来源清单并验证允许的访问方式、可用字段和实际成本；至少打通两个可用来源后再开展持续任务。搜索服务若需要密钥，属于待配置依赖；免费额度、授权条件和可持续供给需验证，不能直接以网页批量抓取替代未获得的接口。社交平台在获得适当接入条件前，仅通过允许的公开页面、搜索已收录内容和人工链接补充参与，不承诺完整平台覆盖。

500元预算下，第一版优先复用搜索结果、只深入分析有价值的候选、先做主体排重再调用模型、只为高优先级企业补充联系方式。付费企业库与多平台商业接口不设为第一版必选依赖。

每个渠道独立记录：待验证、待授权、可用、受限、故障、停用。每次运行展示实际覆盖渠道、时间范围和失败情况；单渠道故障不阻塞其他渠道。不能以“零结果”掩盖未接入或失败。

平台内图像、视频语音的 OCR/转写列为后续增强，前提是内容获取与处理获准。第一版优先标题、正文、简介及允许获取的结构化字段。

## 5. 企业发现、归一及排重

- 标准企业档案包括法定名称、简称、品牌、统一社会信用代码（如公开可得）、官网域名、主体地址、行业、业务类型及平台账号。
- 企业归属证据可来自官网互链、官方认证、公开主体标识等；仅有昵称相似或同一城市不足以认定同一主体。
- 优先用可靠主体标识归一；名称、域名、地址等作交叉校验；同名、集团、分支机构及品牌与运营公司关系保留冲突状态。
- 多平台内容可以合并到一个企业，但保留原始来源。转载的同一消息不算多份独立佐证。
- 企业、联系人和平台账号分开建档并关联。一个主体多个账号、一个品牌多个运营主体均应可表达。
- 不得将法定代表人自动认定为财务、跨境业务负责人或实际采购决策人。
- 支持已合作客户、已跟进客户、不适用主体、明确拒绝联系主体的排除名单。

## 6. 业务识别与需求判断

输出四个独立维度，不能用一个分数混在一起：

1. 出海业务状态：已观察到实际业务、筹备出海、仅有相关信号、证据不足、非目标。
2. 产品适配状态：符合已配置条件、部分符合待核实、不适配、产品条件不足无法判断。
3. 需求状态：明确表达、存在潜在场景、未知、已知当前无需求。
4. 可联系状态：有公开商务渠道、渠道待核实、未找到、禁止联系。

| 信号 | 可以支持的判断 | 不可以直接推出的结论 |
| --- | --- | --- |
| 企业发布具体出口订单、海外店铺、海外客户业务 | 存在出海业务的证据 | 正在寻找收付款服务商 |
| 招聘外贸或跨境运营岗位 | 业务布局或扩张线索 | 已发生跨境交易、交易金额或币种 |
| 公开询问收款账户、到账速度、结汇费用或服务商 | 在主体、时间与语境匹配后可标注明确需求 | 必然适合我方产品或愿意成交 |
| 外文官网、海外展会、境外商标 | 辅助信号或筹备信号 | 当前已有跨境资金流 |
| 搜索摘要含“收款难” | 待核对候选证据 | 企业自身遇到该问题；可能是转载或服务商广告 |

需求类型按收款、付款、换汇分别记录，并可细分平台回款、B2B货款、服务贸易收入、供应商付款、海外经营支出等。国家、币种、平台、支付频率和金额只有存在依据时填写，否则为未知；业务场景推断须明确标记为推断。

针对聚合跨境支付产品，补充“聚合适配线索”：

| 观察信号 | 产品关联假设 | 需要进一步核实 |
| --- | --- | --- |
| 运营多个海外销售平台或收款渠道 | 可能存在渠道分散与统一管理需求 | 实际渠道、现有收款方式、是否希望统一管理 |
| 服务多个市场或明确涉及多种结算币种 | 可能需要多币种收付支持 | 实际交易币种、收付方向、当前处理方式 |
| 同时有境外收入与供应商/经营支出 | 可能同时需要跨境收款和付款 | 各交易场景、合作方及产品是否实际支持 |
| 公开表达多个账户对账、收付款流程繁琐等问题 | 在主体和语境匹配时构成较强的整合需求信号 | 问题是否仍存在、能否由本产品解决 |

以上是检索和核实方向，不表示产品已经具备统一对账、自动路由、特定平台直连等未由用户确认的功能。报价更低、到账更快等优势也不能自行推定。仅有多市场或多币种信号时，需求仍记为潜在场景；明确寻求整合服务才可按证据标注明确需求。

产品能力以可维护的“国家/币种/渠道/收付方向/主体类型/行业/准入条件”矩阵表示，每个条件为支持、不支持、待确认。用户所述“大部分国家和货币”保留为产品概述，不自动转换成全部支持。缺少关键准入条件时只能标注“可能适配，待核实”，不得进入要求已核实适配的A级。

证据结构至少包含：主张、原文短摘、原始链接、发布者、主体关联依据、内容发布时间（可未知）、发现时间、最近核验时间、证据强度、适用结论和冲突说明。页面抓取时间不能替代内容发布时间。

建议明确需求按近30天优先核查，业务动态按近90天优先，长期官网业务介绍作为背景；窗口可配。旧证据降低跟进优先级，不能单凭过期认定企业无需求。

分级建议：

- A：目标区域与主体已核实，产品适配，有近期明确需求及有效证据，至少一个可用商务联系入口。
- B：实际出海业务证据较强，产品可能适配，但只有潜在需求或关键条件待核实。
- C：仅有较弱信号、主体待确认或证据不足，需要补充调查。
- 不适用/禁止跟进：产品不匹配、误识别、已拒绝或其他明确排除条件。

可在各级内部按适配程度、信号强度、时效及联系便利度排序。排序分是业务优先级，不等于成交概率。模型输出必须引用已获取证据；无依据返回未知。

## 7. 联系方式采集与验证

采集优先顺序建议为：企业官网商务电话/邮箱 → 官方账号公布的业务联系入口 → 公开且用途明确的负责人商务联系方式 → 经授权的企业数据补充。

| 字段组 | 内容 |
| --- | --- |
| 联系内容 | 企业总机、商务电话、邮箱、官网联系表单、公开商务微信、企业微信入口、抖音号/主页、小红书号/主页、公众号名称/标识、视频号入口 |
| 联系对象 | 企业、部门或个人；公开姓名、岗位、所属主体、岗位关联证据；不知道则留空 |
| 来源与用途 | 具体来源链接、公开用途、发布时间或采集时间、最近核验时间 |
| 验证状态 | 仅提取、格式有效、主体关联已核实、人工确认可用、失效、冲突、禁止使用 |

格式正确不等于号码可接通或邮箱可送达；平台账号存在不等于能够私信。第一版不通过自动拨打或群发来验证，不猜测个人邮箱或补全隐藏手机号。缺失字段留空，不承诺每家企业都有负责人直联方式。

个人联系方式仅处理合法公开且与商务用途相符、范围必要的信息；明确拒绝者停止使用。公开信息也需满足适用处理条件，并提供更正、删除和停止联系机制。企业联系方式与可识别自然人的联系方式分别管理。[《个人信息保护法》第6、19、27、44—47条](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)。

## 8. 定时、增量与资源控制

- 支持手动运行、定时运行、暂停、恢复、终止和指定范围补跑；使用 Asia/Shanghai 作为建议业务时区，最终可配置。
- 建议每天发现新线索、每周复查重点企业；时段及频率由来源配额和预算决定。
- 采用内容指纹、主体标识及运行游标增量处理；任务重试不能重复创建企业或重复发送同一条消息。
- 只有新增企业、出现新需求、增加商务渠道或重要状态变化才重新进入提醒队列；普通页面更新不应反复推送。
- 来源限流、授权失效、验证码或访问限制发生时暂停该来源或转人工处理，不绕过访问控制。
- 配置单次和每日费用上限、页面/查询量上限、超时及有限次重试；超预算后保留进度并展示未完成原因。
- 记录每次任务的开始结束时间、实际覆盖、原始候选量、去重企业量、各等级线索量、渠道覆盖、错误及费用。
- 不对未能访问的互联网范围声称“全网覆盖”；不以固定有效线索产量作为早期系统可用性承诺。

预算控制：日/月累计计算搜索、模型、数据服务的实际费用及尚未入账的调用估算，记录计费来源和价格配置日期；免费调用也记录用量。在月预算70%（350元）、90%（450元）时提示消耗情况，达到500元前停止会导致超限的新增收费调用，并保留已完成结果。尽量预估调用上限，计入在途请求，避免只在账单到账后才停止。没有可靠价格或额度信息的收费来源先不启用。

本地运行时需检测机器离线、休眠和任务漏跑。恢复后按配置补跑并标明迟交；本地关闭期间不能承诺持续运行。是否迁移到常在线环境及其预算另行配置。

## 9. 交付、审核与跟进

第一版确定为定时Excel清单（.xlsx）＋简短日报；后续优先预留API/MCP接入，工作台及CRM同步为可选扩展。

Excel建议包含：

| 工作表 | 内容 |
| --- | --- |
| 本期新增 | 本期首次交付、去重后符合门槛的新客，一企业一行，按优先级排序 |
| 重要变化 | 已交付企业新增需求、联系方式或重要状态变化，与新增数量分开统计 |
| 联系方式与证据 | 以企业ID/线索ID关联多个联系人、账号和证据；每条保留来源及验证状态 |
| 运行摘要 | 批次、覆盖区域/来源、失败原因、费用、数量、交付缺口及下次计划 |
| 跟进反馈 | 线索ID、销售负责人、联系结果、需求确认、无效原因、下次跟进时间，支持回传导入 |

主表设置筛选、冻结表头、可点击来源链接。电话、平台ID等按文本保存，防止丢失前导零；外部文本以文本方式写入，避免被当成Excel公式执行。每次输出包含稳定企业ID、线索ID、批次ID和结构版本，方便反馈关联和后续接口迁移。

建议工作日每天09:00（Asia/Shanghai，UTC+8）交付新增清单及日报，每周一汇总上一周结果；时间为可调整建议，文件保存位置或发送渠道待确认。调度以真实完成情况记录，不伪造准时交付。

周交付规模：以每周100个以上可跟进潜在商机作为待验证的规模目标，结合销售实际容量配置。建议按5个工作日组织交付，日均约20条是规划参考，不是每日硬性保底；可在有充足合格线索时增加交付。不得为凑数放宽证据门槛，数量不足时说明来源覆盖、费用、样本量及缺口。

“可跟进潜在商机”定义为：目标区域和主体有可靠依据，有实际出海业务证据，至少一个归属明确的公开商务联系入口，产品没有已知不适配条件、待确认项已标出，需求至少达到有证据的潜在场景，并且不在已合作/拒绝/无效排除名单中。A/B级为销售清单主体；证据不足的C级留在待研究池，不计入周商机目标。

按去重企业统计周新增；已合作客户、同企业多个联系人、不同平台的同企业、仅有存量更新、已交付企业的重复出现，均不能充作新商机。联系人可用性与客户真实需求通过后续人工联系反馈单独统计。

标准清单字段：企业名称、城市与地址口径、行业、出海状态、目标市场、业务场景、产品适配、需求状态、等级、关键证据链接与日期、联系方式及验证状态、首次发现/最近更新日期、负责人、跟进状态、建议核实问题。

后续工作台应能按地区、行业、等级、需求类型、证据日期、来源、联系方式类型和跟进状态筛选；查看企业详情、原文证据、冲突信息和变更记录；支持人工纠错、合并拆分、认领、导出及排除。

销售状态建议：待审核 → 待跟进 → 已联系 → 需求确认 → 商机 → 成交/未成交；另设无效、暂缓、拒绝联系。必须区分“找不到联系方式”“联系不上”“无需求”“需求存在但产品不匹配”。

每日摘要展示新增合格企业数、重要变化数、A/B分布、优先核实项、实际来源覆盖、失败情况和费用，附Excel位置。待研究C级数量单列，不与可跟进数量混合。通知渠道待确认；带个人联系方式的数据默认仅在受控清单或详情中展示。后续CRM同步须处理字段映射、重复记录、负责人归属及失败重试。

第一版保留人工跟进；自动邮件、短信、私信、加好友、拨号及群发作为另立范围的能力，不随线索采集默认启用。

## 10. 安全与可维护性

- 使用渠道适配器和版本化规则，地区/行业/关键词配置变化无需改代码；新来源通过适配器扩展。
- 密钥与授权凭据通过专门的密钥配置保存，不进入页面内容、模型提示、导出文件及普通日志。
- 网页正文、评论、文档及搜索结果均是待分析数据，其中的指令不能改变Agent的任务、权限或工具调用目标。
- 对外部页面提取字段做校验；保留模型、提示及规则版本，支持依据同一证据复查结论。
- 联系方式按角色限制访问与导出，导出和修改有记录；设置必要的保存期限和删除机制。
- 明确企业和联系人数据的存储位置、模型服务商接收的数据范围及第三方处理边界；模型默认只接收判断所需业务证据，联系电话等无需用于推理的字段避免发送。

API/MCP扩展要求：第一版即保留结构化存储，Excel是交付视图，不作为唯一数据源；明确企业、联系人、证据、线索、任务批次和跟进反馈之间的关联。后续接口支持按更新时间增量查询、过滤、分页、读取详情、回写反馈和查询任务状态；读取与写入权限分开，写入反馈可重试且不重复，个人联系方式按调用方权限返回。MCP使用同一业务接口，不另建一套不一致的数据逻辑。第一版只落实数据结构和业务边界，不以对外接口已部署作为交付条件。

## 11. 分期建议

P0 接入与样本验证：补充产品能力矩阵和目标地区，导入三个现有客户作为种子及排除项，验证至少两个可用公开或授权来源，整理一批代表性样本，确认字段、判断口径、渠道条件及实际成本。

P1 最小可用闭环：定时发现、企业归一、出海和需求分级、公开商务联系方式补全、来源追溯、人工审核、Excel清单＋简短日报、反馈导入、增量更新、失败报告与500元月预算限制。优先打通搜索、官网和当地公开企业信息来源，结构化数据支持后续扩展。

P2 渠道与接口扩展：按实际获批、用途条件和预算接入抖音、小红书、公众号/视频号；提供API/MCP查询与反馈接入。工作台、团队分配及CRM同步按后续需要增加。

P3 优化：在允许的来源上加入OCR/语音转写、利用人工反馈调整排序、扩展城市及行业。反馈用于版本化迭代，不未经验证直接改线上判断规则。

## 12. 建议验收口径

先以人工标注样本建立基线，再冻结正式门槛。建议试运行1—2周、积累约100家候选企业，并从输出中分层抽样至少50家（各级均覆盖；不足则全量）。以下数值仅供协商。

| 验收项 | 口径/建议 |
| --- | --- |
| 来源可追溯 | 每条输出的业务结论和联系方式均有具体证据链接与时间记录，缺证据不标成已核实 |
| 高等级准确性 | A级中实际满足目标区域、主体、出海、产品适配与明确需求条件的比例，建议目标≥80%；无足够A级样本时报告样本不足 |
| 主体匹配 | 抽检账号、品牌、联系方式与企业归属，报告错误类型及比例，目标结合样本确定 |
| 联系渠道覆盖 | 有至少一个公开商务入口的企业数/目标企业数，区分邮箱、电话、社交账号和表单，不提前承诺固定比例 |
| 联系方式真实性 | 分别统计来源存在、归属正确、人工确认可用；不能把格式校验当成可用性验证 |
| 排重和更新 | 同主体跨来源合并，冲突进入人工队列；重复运行不重复建档或推送 |
| 调度与故障 | 验证计划运行、暂停补跑、授权过期、来源限流、单来源失败及预算耗尽时的实际行为 |
| 销售价值 | 跟踪有效联系、确认需求、转商机及成交情况；注明观察周期和分母 |
| 周交付规模 | 单独评估能否在既定区域、质量门槛和500元预算内达到100条以上去重可跟进新商机；未达标需报告缺口，不以C级或存量更新充数 |
| 清单与反馈 | Excel能正常打开、筛选、追溯证据；多联系人归属正确；反馈按稳定ID回传后不产生重复企业或覆盖较新的反馈 |
| 预算上限 | 费用汇总、阈值提醒、在途请求预估、停止新增收费调用和保留结果的行为符合配置 |

覆盖率仅针对明确的输入集合或来源范围评估，不以无法知道的“全网企业总量”作为分母。渠道失败必须计入运行覆盖说明，不从报表中隐藏。
