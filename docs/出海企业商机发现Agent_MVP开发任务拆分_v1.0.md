范围按上述文档组合解释：MVP清单确定最小交付，技术文档明确纳入本地基础FastAPI，最新DeepSeek方案调整发现方式，其余业务规则沿用正式需求。冲突和本次实施建议列明如下，不静默扩大范围。

| 差异 | 本次任务基线 |
| --- | --- |
| 原MVP使用固定目录发现，旧补充方案优先SearXNG；用户现改用DeepSeek | 先完成DeepSeek Search＋原文/官网补全；暂停SearXNG部署及引擎验证，不自动回退或切换供应商。固定名单仍可作种子 |
| 原MVP将API延后；技术方案纳入基础FastAPI | 实现技术文档第6章的8个本地接口；公网接口、MCP、反馈写入接口不纳入 |
| 原MVP抖音延后；补充方案允许可选渠道 | O01—O03独立增量，默认停用，不阻塞Web闭环，不能把接口占位算作真实接入 |
| 完整一期要求至少两个独立来源 | MVP按补充方案验证Web发现及证据补全，不强制两家搜索服务或抖音；分别报告发现渠道、搜索上游和实际内容发布主体 |
| 完整一期要求反馈导入、合并撤销、暂停/取消、断点续跑 | MVP保留Excel人工备注、配置排除、冲突待研究、完整重跑及中断识别，不实现这些完整一期能力 |
| 技术任务状态与完整一期存在差异 | 使用QUEUED、RUNNING、SUCCEEDED、PARTIAL、FAILED、BUDGET_STOPPED、INTERRUPTED；任务、来源及导出状态分别保存 |
| 技术示例为8张表，数据源补充新增缓存 | 8张业务表＋search_cache，共9张；pages增加metadata_json。不引入完整一期14类实体全量建表 |

交付边界：单机、一个FastAPI进程、一个串行Worker、一个本地SQLite、DeepSeek模型供应商（deepseek-flash）、三表Excel及Markdown日报。DeepSeek Search为外部HTTPS服务，不部署本地搜索容器。自动触达、后台、CRM、OCR、音视频处理、外部发送均延后。

## 2 任务口径与里程碑

共拆分 **37项MVP任务＋3项抖音可选任务**。所有任务初始状态为“未开始”；文档存在不代表相关能力已完成。建议负责角色用于后续分工，实际人员及计划时间待填写。

优先级：P0为前置验证及从首次真实调用起就要生效的控制；P1为MVP交付必需；P2为可选渠道。依赖表示完成该任务验收前必须满足的前项；无依赖任务可立即开始。配置模板、离线样本和契约开发可以先行，真实运行另受第5章条件约束。

| 里程碑 | 任务 | 建议负责角色 | 退出条件 |
| --- | --- | --- | --- |
| G0 来源与配置验证 | T01—T04 | 产品/业务、后端、部署、测试 | DeepSeek Search真实可用；可取原文及归属依据；缺口、使用条件、成本和样本有记录 |
| G1 工程与存储 | T05—T08 | 后端 | 可安装、配置可校验、9表可迁移、事务及仓储可用 |
| G2 企业与证据采集 | T09—T17 | 采集/后端 | 搜索→原文→企业→官网→联系入口落库；重跑及冲突行为正确 |
| G3 分析与费用控制 | T18—T22 | 后端/模型、业务 | 有证据的结构化分析、本地A/B/C规则、可复用缓存、调用前预算控制 |
| G4 结果交付 | T23—T25 | 后端 | 三表Excel、日报及发布清单可用；发布中断恢复不重复计新增 |
| G5 服务与运维 | T26—T33 | 后端、部署 | 本地API、单Worker、CLI调度、保存清理、备份及运行手册可用 |
| G6 集成与业务验收 | T34—T37 | 测试、业务、运营 | 故障验证及真实样本记录齐全；技术闭环与业务闭环结论分开 |
| GX 抖音增量 | O01—O03 | 采集、部署、业务 | 条件成立才接入；不可用时不影响Web任务 |

开发顺序不要求等到前一里程碑所有事项结束才开始后一阶段。例如T05—T09、T18及T26可以在来源验证期间开展离线实现。预算、限速、凭据隔离、日志从首次实际调用开始生效，不等G5或G6补做。

## 4 高风险契约的实施约定

以下是基于技术方案的实现细化，编码时保持一致；若实测需要调整，更新本文件与对应验收，不由模型临时决定。

1. **身份与证据**：可靠标识优先；没有可靠标识时保留候选/冲突及匹配依据，不能靠名称强并。搜索命中城市不等于企业在珠海；摘要不等于原文。page_id、短摘、主体及地区归属都通过验证后才进入业务判断。
2. **两个缓存**：search_cache复用搜索结果；分析缓存复用业务事实。纯采集时间不改变事实缓存或交付指纹。产品规则、联系归属/失效、排除项和时间窗口变化必须重跑本地规则。页面访问失败不能直接推断企业无需求。
3. **预算先行**：cost_calls区分预留、结算、明确未调用释放、费用未知；具体状态名由T18固化。每一次收费重试都视作新尝试。配置无保守费用上限时可以运行离线测试，不允许真实收费调用。
4. **先快照再交付**：run_items冻结本次视图；首次交付资格只在成功发布后写入。首次采集为C、之后变成B，应计首次合格交付；已交付A/B更新不重新计新增。若新排除/失效发生于导出前，必须在冻结快照前检查。
5. **恢复顺序**：取实例锁→检查发布清单补记交付→标记遗留RUNNING为INTERRUPTED→核对费用未知项及维护状态→允许领取。备份恢复另需核对备份后费用、拒绝和删除处置，不能凭旧库余额自动继续收费。
6. **保存与删除**：T31使用命令和本地记录，不增加后台或反馈导入。若实现需要独立处置日志或维护状态，记录在受控本地运维文件并纳入备份/恢复规程；不要把删除记录仅存在将被恢复覆盖的旧备份里。运行中的任务使用冻结配置，新排除/删除须在下一次交付前生效。
7. **单机保护与外部搜索边界**：DeepSeekSearchClient只访问固定DeepSeek HTTPS端点；普通Fetcher始终校验公网地址及允许域名。CLI不启动第二个业务执行器，维护操作与Worker互斥。配置、日志及快照都不能保存凭据值。
